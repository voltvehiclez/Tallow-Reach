# src/ui: HUD, outpost screens, pause menu

Reads `state`, calls sim actions. No game rules here.

| File | What it does |
|---|---|
| `hud.js` | In-flight HUD (ignores hurt events for other players): bars, remaining route beneath Boost (remaining system names with arrows, current system blue, destination marked bold amber, and destination heading with the count of systems still to enter; scrollable if long and refreshed on travel and twice per second), cargo and contract readout, lock ring, markers, and the beam progress bar with percentage (small, directly under the "left in rock" hint, shown only while the beam is cutting). Hints persist until the next sim tick so high-refresh screens do not flicker. |
| `screens.js` | HTML for the intro and each outpost tab. Pure functions of state. `TABS` and `SCREENS` list the tabs. The Shop tab draws whatever `shopList(shopId)` returns from `data/shops.js` for the current station feature's `shop` — its rows, prices and "N left" — so a new row is a data edit. The Inventory tab shows the station's store above one ship's hold (arrows browse the ships; `viewedShip()`), each in a compact grid of clickable item tiles with m³. Click moves one item, Shift-click moves the whole stack, and right-click opens item actions such as Sell. Selling opens a small in-game box beside the selected item to enter a quantity, defaulting to the full stack. Each hold uses a fixed 5-by-5 slot field with a three-row viewport; both grids scroll independently, even when mostly empty. |
| `menu.js` | The outpost panel: `ACTIONS` (one function per button, `data-a` name) and the click handler. Boot/slot/import/reset prepare the saved seed before applying it; safe-recovery notices survive alongside load/import success messages. |
| `picker.js` | Which Outfitting bay picker is open: `toggleModulePicker`, `togglePaintPicker`. Pure, one at a time, tested in `tests/picker.test.mjs`. |
| `outfitting.js` | The Outfitting tab's 3D window: mounts the ship canvas into `#shipview` after every panel redraw, wires drag/zoom, draws one frame per game frame. |
| `pause.js` | The pause overlay: PAUSED title, resume hint, sound on/off switch, Resume button. P closes an open starmap first, then pauses; Esc only closes the chart. |
| `starmap.js` | The M chart: visible system web, gate lines, current/selected markers (visited knowledge is retained without a separate light-blue style), inspect dropdown and zoom/pan/labels. Zooming into a selected system dot opens a derived pocket map with a short zoom transition: pockets orbit a visual-only star/black hole with a permanent two-line name/type label; native hover tooltips are gone from pockets/core, while click popups remain. Core radii are map units so the graphic scales with system zoom; pocket dots/labels stay screen-sized. Galaxy pan is bounded to 0.5–1 screen pixels per pointer pixel, increasing gently when zoomed out. Free-warp systems omit ordinary internal lines; route-only systems draw them. When a route is active, consecutive pocket hops in the viewed system and the outward gate exit get orange dashed overlays with directional arrows, even in free-warp systems; galaxy route links use the same treatment. Gate exit stubs point toward neighbouring systems, gate pockets and their labels can be double-clicked to open the peer map, and neighbouring-system labels are clickable travel targets quoting the reciprocal gate pocket. Closing/reopening restores the session-only view and framing; on cross-system travel a remembered pocket view follows the local pilot to the new system (resetting pocket framing), while the galaxy view stays open at galaxy level. Right-click a galaxy system to set a saved destination or, when at its direct gate, warp to it. Pocket and gate-peer popups also offer **Set destination** for the exact pocket, including when it is not directly reachable. Straight connections meet their endpoint dots; chart-only node layout avoids unrelated dots; a highlighted path and route stops appear beneath the pocket rows (long names wrap), with pagination only when the available space cannot fit them; J in flight advances one checked warp hop. The right panel is a compact system/current-pocket/pocket-row overview. Clicking/right-clicking a pocket dot or gate-neighbour label opens a **Warp to** popup only for a legal hop (any local pocket by default, or an explicit route) and emits `action { name: "travel", to }`; main calls `startWarp`, which rechecks it. Single-player chart pauses the frame gate and releases flight input; a future hosted world keeps running. |
| `route-display.js` | Shared route presentation for the HUD and starmap: remaining system names with arrows, blue current system and bold amber destination, respecting discovery visibility. |
| `warpflash.js` | The warp vignette and white-out. Two gradients, updated from `state.warp` each frame. |

Rules:
- Buttons carry `data-a` (action name) and optional `data-b` (argument). The Shop's Buy button is
  `data-a="wb" data-b="shopId:itemId"`. The panel re-renders and autosaves after each click.
- Styling lives in `src/styles.css` (labelled sections; the pause menu has its own).
- New tab: `docs/HOW_TO_ADD.md` recipe 7.
- Inventory buttons carry `data-a="mv"` with `data-b="kind:id:dir:n"` (kind `c` goods or `m` module — only what the tile shows, since one `moveItem` moves either — dir `s` station to the ship shown or `t` back, n a count or `all`). The tiles come from `itemsAt(place)` in `sim/inventory.js`, which lists goods in catalogue order and then spare modules in the order they arrived.
- A bay opens a picker: `data-a="slot"` (module, `data-b` is `group:bay`) or `data-a="paint"` (paint, `data-b` is the paint id). The rule lives in `picker.js`.

`chart-lines.js` computes a cached, derived visual layout that nudges unrelated dots away from straight gate connections; it does not alter simulation positions. In crowded cases the chart masks only obstructing unrelated dots, never both endpoints globally. Highlighted routes reuse the same straight geometry.
