# src/data: tuning and content tables

Plain objects and numbers only. No imports from other layers (except other data files). Safe to edit for balance.

| File | What it holds |
|---|---|
| `simulation.js` | Fixed simulation tick (`SIM_DT`), maximum accepted render-frame time (`MAX_FRAME_DT`) and how often the resume point is autosaved (`AUTOSAVE_SECONDS`). |
| `mounts.js` | Named hull-local gun, missile and beam mount offsets, shared by the sim and `PlayerShipView`. |
| `ships.js` | Hulls the player can fly, and the `FLIGHT` table that scales every ship at once. A hull has no `spd`/`turn` and no Hull HP of its own: the fitted thrusters set speed and turn (`sim/drive.js`), the fitted shields set shield strength and recharge (`sim/shield.js`), the fitted hull module sets Hull HP (`sim/hull.js`), and an empty thruster bay means the ship cannot move. |
| `items.js` | `ITEMS`: the whole item catalogue — every ore, salvage good, mission object and **module**, keyed by id, with a category (`cat`), sell value (`v`), volume in m³ (`vol`) and stack rule (`st`). Mission objects may set `v: 0` and are not sellable. A module's entry is `{ cat: "module", v: 540 }`: its name, volume and stats live in `modules.js` under the same id (`npm test` checks both directions), and `v` is what a spare part sells for — 60% of its shop price, never below 1 credit. Adding an item is one line; read them through `itemName`/`itemVol`/`itemValue`/`canSell`/`isModule`, never by hand. |
| `weapons.js` | The missile's flight and lock-on numbers and the ammunition price (`unitPrice`). Guns, the mining beam and the missile launcher are modules (`data/modules.js`), not weapon data. |
| `shops.js` | `SHOPS`: what each shop sells and charges. Per shop a heading (`n`), its line of explanation (`d`) and `stock` — one row per item, and the only way a part appears on the screen: `id` from `items.js`, `price`, the row's own `n`/`d`, and optionally `max` (leave it out: never runs out; a number: `N left`, sells out). Optional `own: false` hides the "You own N" count. A station feature in `places.js` names its shop (`shop`). Bought through `sim/economy.js` `buyItem(shopId, itemId, qty)`. |
| `station.js` | Base modules, their costs, storage and refinery numbers, repair and recovery fees. |
| `contracts.js` | Compatibility re-export of the mission contract templates. New mission/contract data lives in `missions/`. |
| `missions/` | Mission vocabulary plus data-only contract and story definitions. Each active mission uses `{ id, title, kind, requires, steps, rewards, fails }`; each player-facing step can provide a spoiler-safe `objective` sentence, while `log` remains compatibility/internal text. 13b story steps cover dialogue/choices, scripts, waits, flags/branches and parallel objectives. The runner is in `sim/missions.js`. |
| `places.js` | Systems (non-flyable groupings) and pockets (flyable places): authored `PLACES`, `PLACE_DEFS` features (station, asteroid field, spawner, planet, encounter), generated `template` ids, explicit `PLACE_LINKS`, `DEFAULT_PLACE`, `pocketsIn`/legacy `nextPocket`, and `PLACE_EXTENT`. `setPlaceCatalog` installs the resolved seed galaxy as the live lookup catalog on boot/load/import; lookups fall back safely to the starting pocket. Internal ids are save ids. |
| `galaxy.js` | Starmap tuning: `GALAXY` (seed, system count, organic layout, degree cap/depth tuning, visibility policy, advisory difficulty, free intra-system travel default with a per-system `intraSystem: "links"` opt-out, empty route cost/requirements, varied generated `stationNameStyles`, galaxy chart padding/radii/zoom, `panSpeed`/`systemEntryZoom`/`transitionMs`/popup `context`, and `systemMap` orbital radii/padding/exit length/zoom plus 5% black-hole chance, map-unit core radii and label offset/line-height/gap), `GALAXY_OVERRIDES` (move system/pocket `mapPos`, author visual-only `core`, delete/promote/route edits by stable id) and `SYSTEM_NAME_PARTS`. Resolved by `sim/galaxy.js`, installed by `sim/galaxy-session.js`, and read by the live M starmap and warp rules. Pocket map layout is derived, not saved. |
| `terms.js` | Generic player-facing nouns: `TERMS.mapNode` ("system") and `TERMS.flyable` ("pocket"), each changeable in one line; `term`/`Term`/`terms` helpers. |
| `sectors.js` | Warp timing and curves only (`WARP`, `WARP_TIME`, `warpFlashAt`, `warpPhaseAt`, `WARP_COAST`). Geography lives in `places.js`. |
| `outfitting.js` | `MODULE_GROUPS` (name and description per bay group), `SHIP_LAYOUTS` (how many bays each hull has of each group), `layoutFor`/`slotsFor`, and `APPEARANCE_SLOTS` (the paint bays under the hull). |
| `encounters.js` | `ENCOUNTERS`: hostile patrols, friendly traders, derelicts and resource caches, with references and slow respawn timers. |
| `place-templates.js` | `PLACE_TEMPLATES`: reusable generated-pocket scenery and tiered encounter pools. Generated gate trader features are suppressed for station-pocket detachment unless an author explicitly opts into gate co-location; `features`/`extraFeatures` are preserved as explicit additions. |
| `enemies.js` | `ENEMIES`: every hostile, keyed by id — name (`n`), plural name (`pl`), Hull HP (`hp`), colour (`col`), scale, faction (`f`), behaviour (`ai`) and all its numbers (speeds, ranges, fire gap, damage, bullet speed, spawn distance). `DEFAULT_ENEMY` is what the spawner falls back to; `enemyDef(id)` looks one up. Adding an enemy is an entry here. |
| `loot.js` | `LOOT_TABLES`: what a kill drops (`kind: "drops"` — a line per drop with a chance `w`, a count range `c` and a scatter `j`), what a derelict leaves behind, and the ore a rock is made of (`kind: "pick"` — weighted `w`). Rolled by `sim/loot.js`; an enemy names its table with `loot`. `DEFAULT_LOOT` is the fallback. |
| `factions.js` | `FACTIONS`: who a hostile belongs to (`pirates` today), with a name and a description. An enemy names one with its `f` field and the id travels with the `enemy-killed` event. |
| `modules.js` | `MODULES`: every part that can sit in a bay (`g` group, `vol` m³ it takes in a hold or in storage, `n`, `d`, and the stat it feeds: `mjps`, `mj`, `spd`/`turn`, for thrusters the power appetite `draw`/`boost`/`ign` and the boost tank `bmax`/`buse`/`bfill`, for shields `sh`/`regen`/`delay`/`draw`/`drain`, and for the hull `hp`, and for primary weapons `dmg`/`rate`/`bspd`/`draw` plus `barrels` for linked multi-barrel guns). `STOCK_FIT`: what a hull is delivered with. |

Rules:
- Keep the short keys (`n` name, `d` description, `v` value, ...). Copy an existing entry when adding one.
- `npm test` (`tests/content.test.mjs`) fails if an entry is missing a field.
- Adding a ship, item or contract type: see `docs/HOW_TO_ADD.md` recipes 1 to 3.
- A module needs an entry in `items.js` as well as `modules.js` (recipe 16 step 1), and a row in
  `shops.js` if the player should be able to buy one (recipe 4).
