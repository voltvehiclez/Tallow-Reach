# src/sim: gameplay rules

Rules of the game. Reads and changes `state`, talks to other systems with events. Imports `data/`,
`state/` and `util/`. **It holds no mesh, no material and no scene** (refactor steps 7a and 7b): an
enemy, a bullet, a missile, a crate, a spark, a rock and the player's own ship are plain records, and
`render/views.js` draws them. Step 7c removes the remaining render imports: place entry
emits `place-entered`, and missile lock reads the camera direction supplied in `state.aimDirection`
by the frame loop. Named weapon mounts come from `data/mounts.js`, transformed by `pilot.js`.
**It never touches the speakers or the keyboard:** a sound is `emit("sfx", { name })` (played by the
`SFX` table in `core/audio.js`) and the pilot's intent arrives in its `controls` record (filled for the local player by
`core/input.js`, shape in `state/controls.js`). `tests/layers.test.mjs` keeps all of that true.

| File | What it does |
|---|---|
| `step.js` | `stepSim(dt)` runs the gameplay systems in order; `createSimClock()` feeds it 60 fixed ticks per simulated second and caps long frames. `isSimulationPaused()` is the frame gate: only the pause card and the title screen stop the clock. The starmap and the in-flight ship inventory are read-only overlays — they release flight input, but the world keeps running behind them in every mode. |
| `player.js` | `createPlayerRecord()` creates an independent player with its own controls; `createPlayer()` places the local one in the list and binds `state.profile`. Ship setup (`setShip`), `flight(dt, player)` and `hurt(d, player)` operate on that player's own runtime and portable `profile` (`configurePlayer` sets up a non-local fit and profile; hull hits stamp `profile.hp[ship]`). A ship with no drive gets no thrust and no turn, and pressing a control warns "Equip thrusters to move". |
| `shield.js` | The ship's shields from the fitted module: `shieldOf` a loadout, `refreshShield` after a fit, ship change, load or dock, `updateShield` each frame (accepts an explicit player; defaults to local; off while being hit, then `regen` a second after the `delay` lull). Also charges the ship a flat `shieldDraw` MJ/s for keeping them up, and bleeds them away when the ship cannot pay. |
| `power.js` | Ships' power budget: `powerOf` a loadout, `refreshPower`/`refillPower` after a fit change, `updatePower` each frame, and `hasPower` to ask whether the ship can pay for a demand. `setDraw`, `hasPower` and `updatePower` accept a player or an explicit power budget; the default is the local `state.power` for the HUD; `draw` is set by the thrusters in `sim/player.js`, the shields in `sim/shield.js`, the guns and the beam in `sim/weapons.js`. |
| `hull.js` | The Hull HP the fitted hull module grants (`hull_basic`: `hp` 10) and `refreshHull()` after a fit change, a ship change, a save load or a dock. No module fitted means no Hull HP — any hit reaching the hull kills the ship. The saved fraction in `profile.hp[ship]` is applied; nothing here repairs. |
| `drive.js` | The ship's drive: `driveOf` a loadout, `refreshDrive` after a fit, ship change or undock, `hasDrive` to ask whether the ship can move at all. Writes the player's `drive = { spd, turn, draw, boost, ignite, bmax, buse, bfill }` and sizes the boost tank (`player.enMax`), which the flight model and the chase camera read; `driveDraw` works out the per-second power the pilot is asking the thrusters for, and `ignite` is the one-off slug for lighting the boost. No thruster fitted gives 0 / 0: no thrust, turn or boost. |
| `fitting.js` | Moving modules between bays (`profile.loadout`) and the current station's stock (`worldState.stationStores[placeId:featureId]`): `fitModule`, `unequip`, `storedFor`, `fittedAt`, `ownedCount`. The only writer of `profile.loadout`; refreshes power, drive, shields, hull and guns on the acting pilot after every change. |
| `inventory.js` | Where things are kept and how full it is, in m³. A place is one stock, `{ itemId: count }` — the current dockable station (`worldState.stationStores[placeId:featureId]`, sized by `worldState.base.store`; `worldState.store` remains the home alias) and each pilot's ship holds (`profile.holds[id]`), ore and spare modules alike, because both are items (`data/items.js`). `stockOf`/`holdOf` (a place), `countOf`/`itemsAt`/`unitsOf` (what is there, in the order the screens list it), `loadOf`/`capacityOf`/`freeOf`/`spaceFor` (room, from each item's `vol`), `addItem`/`takeItem`/`moveItem` (the only movers), `discardItem` (trash `n` of a stack, the whole stack by default, for the two-step right-click Discard), `buyItem` (a purchase into the active station), `valueOf` (what a stock sells for, with the world's refinery bonus). Pure: no 3D, so it is tested. |
| `guns.js` | The guns in the primary bays: `gunsOf` a loadout (pure, one `{i, id, dmg, rate, speed, draw, barrels}` per fitted gun) and `beamsOf` (the beam modules there, with `period`/`range`/`draw`), `refreshGuns` after a fit, ship change, load or dock, and `moduleListName` — the short name for a fitted list that the HUD and the equip toast share. Own module so `fitting.js`/`economy.js` can refresh the guns without importing the shooting code. |
| `weapons.js` | Per-player firing, mining, missile stock (`profile.msl`) and lock state; projectile flight advances once per world tick. Firing the fitted guns on left click (each gun on its own 1/`rate` cooldown, one bolt per linked barrel per shot, drawing `draw` MJ/s while the trigger is held), the mining beam (per fitted `beam_basic` module: `period` seconds of continuous contact per ore into the acting pilot's hold, `range`, resetting the moment contact stops), missiles and lock-on (per the fitted `missile_basic` module: `dmg`, `cap`, `cd`; the missile's own flight and lock mechanics come from `data/weapons.js`). Re-exports `gunsOf`/`refreshGuns`. |
| `combat.js` | `fire(..., player)` records the shooter (`owner`) and inherits their velocity; enemy bullets hit the active player they reach; kills credit the killer pilot's `profile.kills` and emit `enemy-killed { ..., player, encounter }`, and crates pull toward and enter the hold of the nearest active pilot with cargo room. Bullets, hostile kills, crates and pickups — all plain records (step 7b): a bullet `{ id, kind: "bullet", place, missionId, pos, quat, v, own, owner, dmg, l }`, a crate `{ id, kind: "crate", place, encounter, encounterType, missionId, persistent, crateSlot, pos, quat, t, item, spin }`. What a kill drops comes from the enemy's table in `data/loot.js`; mission-created shots and ordinary wave loot carry a mission tag so abandonment can remove them without clearing ordinary encounters. Authored mission drops are persistent, saved in `world.missionState` with their item, `slot` and defeat position, restored when the pocket loads, and marked collected only after a successful physical pickup. `slot` tells several crates of the same item apart, so one recovery contract can own nine crates of Salvage without them collapsing into one (`nextMissionCrateSlot` picks the next free one). Encounter crates announce their final pickup so place memory can start a cooldown. |
| `ai.js` | Chooses the nearest active player; the generic spawner reads a place feature's encounter id and checks each active pilot's `flight.spawnT` and `profile.missions` (local pilot first). Hostiles: `spawnEnemy(id, pos)` builds one from its def in `data/enemies.js` (name, Hull HP, colour, scale, faction, every number) and `AI_BEHAVIOURS` holds the ways they fight (`chase`: close in, then circle and shoot). Hunt contracts still select their requested enemy; one-shot patrol features become cleared place memory after their final member dies; mission-tagged waves emit `mission-trigger { trigger: "wave-clear" }` on their last kill, and mission abandonment removes their tagged hostiles, shots and loot. The record itself, and every access to "where is it, which way does it point", is `enemy.js`. |
| `enemy.js` | A hostile as **plain data** (step 7a): `{ id, kind: "enemy", encounter, def, n, f, loot, hp, mx, pos, quat, v, fire, o }`. `enemyPos`, `enemyFwd`, `turnEnemy`, `enemyDist`, `enemyVel` are the only ways to read its position and rotation; `dropEnemy(e)` takes it out of the world and emits `enemy-removed`. It holds **no mesh** — `render/views.js` draws it. |
| `loot.js` | Rolls the tables in `data/loot.js`: `rollLoot(id, rng)` returns drops `{ item, count, scatter }`, `pickLoot(id, rng)` returns one weighted item id. Pure (no screen, no state), so it is tested by rolling tables 10,000 times. |
| `asteroids.js` | The asteroid field. A rock is a record (step 7b): `{ id, kind: "rock", place, slot, memoryId, shape, pos, quat, s0, scale, r, type, ore, max }` — `s0` is its born size, `scale` its drawn size (mining shrinks it, and the collision rule reads it), `slot`/`memoryId` identify its persistent field slot. Its ore comes from the `asteroid` table in `data/loot.js`. `ROCK_SHAPE_COUNT` is how many shapes exist. |
| `encounters.js` | Builds static `derelict` and `resourceCache` features from `data/encounters.js` into crate records, and marks the feature cleared after its final crate is picked up. |
| `place-memory.js` | Owns the simulation-second cooldown records in `state.worldState.placeMemory`: mined rock slots and cleared encounter feature ids. `updatePlaceMemory(dt)` only runs from an unpaused simulation tick; expiry and `respawn-place` events emit `place-memory-ready`, so loaded places rebuild content without direct coupling. |
| `targeting.js` | Target lock (F). |
| `economy.js` | Cargo, storage, selling, repairs, every purchase. The outpost's one purchase is `buyItem(shopId, itemId, qty)` — the shop is data (`data/shops.js`) and everything it buys lands in the station's inventory through `inventory.js`; `shopList(shopId)` is what the Shop tab draws, and `shopStock()`/`setShopStock()` hold how much a limited row has left (session state, the hook a restock will use). `sellHold()`/`sellStored()` sell everything with a value in a hold or the station — goods **and** spare modules — and return what they sold; `sellInventoryItem(id, where, n)` sells part of one stack. A fitted part is in no stock, so it is never sold. Returns optional message text. |
| `contracts.js` | Compatibility facade for the offer boards; active progress lives in the generic mission runner. Every station has its own offers: `boardAt(placeId, world)` (home keeps `worldState.board` so old saves keep their list; others lazily fill `worldState.boards[placeId]`), `ensureBoard(world, placeId)`, `rerollBoard(world, placeId)`, and `acceptContract(index, profile, world, placeId)` which accepts from that board and rerolls only it. |
| `missions.js` | Data-defined mission runner. Listens for kill, mine, pickup, reach, delivery, trigger, dialogue, inventory, warp-end and simulation-tick events; advances several active missions, runs story dialogue/scripts/waits/flags/branches/parallel objectives, waits for complete scripted item transfers, matches authored physical mission pickups by mission identity and flying state, retries resource-blocked handoffs after inventory changes, docking or the end of arrival warp, keeps a mission whose steps are done (`missionObjectivesDone`) as an active hand-in (`missionHandIn`) until `completeMission` consumes the exact collect/deliver/mine requirement from station stock then ship hold and pays — at the mission's own station only (`missionHandInStation`: its data's `handIn.station`, else the station that gave it out, stamped at accept time; `atMissionHandInStation` and `canCompleteMissionHere` drive the screens, and anywhere else pays nothing and says where to go), shows `handInNextText` meanwhile (never "complete"; a `delivery` contract such as mine reads as its delivery sentence from the moment it is taken and never adds a "You have 2 of 3." tally, because the station store may hold part of the load; a recovery contract instead counts only the crates it spawned — `step.owned`, matched on `payload.missionId`, so two salvage jobs each recover their own — and reports "2 out of 3 crates recovered" through `missionRecoveryText`, while any Salvage in the station or hold pays the hand-in), fails a mission whose mission-only hand-in is lost (death after the last step, or no copy anywhere: `missionLostHandIn`), applies declared failure outcomes only while objectives are open unless the mission's needed item is gone for good, words everything by `missionKindWord` ("Contract"/"Mission"), and emits progress/objectives-done/failure/reward events. Dialogue steps may explicitly require docking for station contact; leaving a sector while any dialogue is open keeps that conversation resumable instead of treating the open panel as abandonment, and world-changing scripts wait for the pilot's authored place/state requirements. |
| `session.js` | `configurePlayer(player, profile)` binds an isolated profile and copies its fit into independent transient runtime; `launch(player)` and `dock(player)` operate per pilot, only clearing transient field entities when no other active pilot remains in space; launching also tops up each open recovery contract's own crates in the field (`ensureSalvageCrates`), one per crate still to be recovered. Local `player-dead` runs ship loss/recovery — the lost hull's records go with it, and the ship you fall back to (another
owned hull, or the Wasp the station lends) is made complete with `addShipRecords`/`ensureShipRecords` before `setShip`, so it
can be fitted and flown; non-local death recovery belongs to step 16. Emits `launched`, `docked`, `died`. |
| `sectors.js` | Per-pilot warp sequence (`startWarp`, `updateWarp`, `cancelWarp`): the starmap proposes an explicit destination, this module requotes the hop (free local warp or explicit gate) and its cost/requirements, then runs the unchanged charge/white-out/settle timing from `data/sectors.js`. Refusals emit `travel-denied`; the legacy no-destination call uses the same travel recheck for old headless callers. |
| `effects.js` | Cosmetic explosions and exhaust, as records: `{ id, kind: "fx", pos, v, l, t, col, size }`. Colour and size are data, so the view needs to invent nothing. |
| `places.js` | Generic place loader (`loadPlace`, `refreshPlace`, `enterPlace`), arrival/station/field helpers. Builds entities from authored `PLACE_DEFS` or generated `place-templates` features, records local system visits in compact galaxy knowledge, and listens for `place-memory-ready` to rebuild expired rock slots/static encounters before emitting `place-entered`. |
| `galaxy.js` | Pure starmap resolution: `generateGalaxy(seed)` runs a replaceable organic-web generator (v2 sparse radial-depth tree; v1 retained to resolve removed legacy gate saves), applies `GALAXY_OVERRIDES`, prunes deleted-pocket links, assigns per-system travel defaults, advisory tiers and independent seeded star/black-hole cores, then indexes and validates one-peer gates and policy-aware reachability. Exposes visibility policies, pocket/link queries, `recordSystemVisit`, `systemCoreName` and `systemPocketLayout` (derived pockets orbit the visual core; author `mapPos` wins, gate dots face their peer; never saved). |
| `galaxy-session.js` | Save/world adapter: `prepareGalaxySave(raw)` resolves the saved seed, installs the live place catalog, sanitizes the save, records the current visit and recovers a removed/unknown pocket safely to home. Failed preparation restores the previous catalog. The resolved web lives in session `state.galaxy`, never in the save. |
| `travel.js` | Pure travel rules used by both the starmap and `startWarp`: `travelQuote`, `canTravel`, `travelOptions`, `findRoute`, `findRouteToSystem` (fewest executable warp hops to any pocket in a destination system), `findRouteToPocket` (exact pocket), and `findDestinationRoute` (dispatches destinations). Reads resolved galaxy policies/links, registered transport modes and requirement handlers; returns plain cost/mode/reason data. Same-system warp is free unless the system opts into `intraSystem: "links"`; cross-system gates always need their explicit link. Route search respects both policies. Non-empty costs are refused until a cost handler exists. No UI, input, audio or runtime state. |
| `world.js` | `clearTransient(placeId)` (docking: hostiles, shots and missiles) and `clearWorldObjects(placeId)` (warping: transient crates and sparks; persistent authored mission crates stay, and rocks stay because they are the pocket's). |
| `entity.js` | **Every entity except a hostile and the pilot's ship** goes in and out of the world here (step 7b): `addEntity(list, e)` gives it an id from `util/ids.js` and emits `entity-spawned { id, kind }`, `dropEntity(list, e)` emits `entity-removed`, `clearEntities(list)` empties one. One place, so a view can never miss one. |
| `pilot.js` | Where the player's ship is (step 7b): `playerPos`, `playerFwd`, `playerDist`, `setPlayerPos`, `facePlayer`, `playerVel`, `playerLocal`, `shipScale`. The ship is `state.player.pos` / `.quat`; `playerPos`, `playerFwd`, `playerDist`, `setPlayerPos`, `facePlayer`, `playerVel`, `playerLocal` and `playerMount` accept an explicit player (otherwise local); mounts also accept a hull id. `playerMount` resolves named mounts; `playerLocal` builds a point in the hull's own frame by hand (pos + scale + quat), never from `matrixWorld`. This is how muzzles, the missile rail, the beam and the chase camera find the ship. |
| `missile.js` | `launchMissile(..., player)` can inherit the named player's velocity (defaults to local); missile flight is shared and advances once per world tick. A missile as a record `{ id, kind: "missile", pos, quat, d, sp, t, l, dmg }`: `launchMissile`, `updateMissileFlight`, and the hit that makes it explode. It homes on the hostile it locked (`t`). |

Rules:
- Use `emit`/`on` to connect systems that should not know each other.
- Never import `core/audio.js`: emit `sfx` (see `docs/HOW_TO_ADD.md` recipe 9).
- Never read `keys`/`pointer` or `core/input.js`: read the acting player's `controls` (recipe 8b).
- Never call `Math.random()`. Use `random()` from `util/rng.js`, so `setSeed(n)` makes a whole run
  repeat; `tests/rng.test.mjs` fails if `Math.random` appears in this folder.
- New rules that need numbers: put the numbers in `src/data/`.
- `docs/HOW_TO_ADD.md` recipes 3, 4, 6, 10, 11 touch this folder.

`navigation.js` implements destination navigation: `jumpRoute` recalculates the next pocket hop and calls `startWarp`, which requotes it. No destination and unavailable routes produce HUD notices; it never automatically chains warps.
