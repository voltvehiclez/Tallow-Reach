# src/ui: HUD, outpost screens, pause menu

Reads `state`, calls sim actions. No game rules here.

| File | What it does |

| `pointer.js` | **One pointer at a time** (playtest 25). `pilotPointer(state)` answers *is the stick live?* — in a ship, not docked, not the title screen, not paused, and no surface holding the flight keys (`pointerTaken`: chat, cargo, cache, starmap, the multiplayer screen, the N list, an act's end card). `main.js` calls `syncPointer()` once a frame; it writes `body.pilot-pointer` only when the answer changes, and `styles.css` draws exactly one pointer from it: `cursor: none !important` everywhere while the orange circle is the pointer (a pinned chat box used to put the white arrow inside the ring), and `#cur` hidden while it is not, so the two are never on screen together. **Free camera (Left Alt) is not a decoupling** — the pilot still flies, from another viewpoint — so it keeps the ring; the rule is a pure function, so it is tested without a browser. |

Rules:
- Buttons carry `data-a` (action name) and optional `data-b` (argument). The Shop's Buy button is
  `data-a="wb" data-b="shopId:kind:id"` (opening the Buy-amount popover). The panel re-renders and autosaves after each click.
- Styling lives in `src/styles.css` (labelled sections; the pause menu has its own).
- New tab: `docs/HOW_TO_ADD.md` recipe 7.
- Inventory buttons carry `data-a="mv"` with `data-b="kind:id:dir:n"` (kind `c` goods or `m` module — only what the tile shows, since one `moveItem` moves either — dir `s` station to the ship shown or `t` back, n a count or `all`). The tiles come from `itemsAt(place)` in `sim/inventory.js`, which lists goods in catalogue order and then spare modules in the order they arrived.
- A bay opens a picker: `data-a="slot"` (module, `data-b` is `group:bay`) or `data-a="paint"` (paint, `data-b` is the paint id). The rule lives in `picker.js`.

`chart-lines.js` computes a cached, derived visual layout that nudges unrelated dots away from straight gate connections; it does not alter simulation positions. In crowded cases the chart masks only obstructing unrelated dots, never both endpoints globally. Highlighted routes reuse the same straight geometry.

At boot, `setupMenu({ beforeStart })` gates Open World on the background model promise, with a disabled “Loading models…” button while pending; the title renders independently.
