# src/ui: HUD, outpost screens, pause menu

Reads `state`, calls sim actions. No game rules here.

| File | What it does |
|---|---|
| `hud.js` | In-flight HUD (ignores hurt events for other players): bars, the complete remaining route beneath Boost (remaining system names with start/intermediate/destination markers, current system blue, destination marked bold amber with a dark center, small orange tick and one dotted outer target ring, and destination heading with the count of systems still to enter; current/start and destination markers are about 20% smaller; no inner route scrollbar; refreshed on travel and twice per second), cargo and every active mission's title plus direct current objective (a recovery contract adds **2 out of 3 crates recovered** underneath; a hunt contract adds its kill count), lock ring, markers, and the beam progress bar with percentage (small, directly under the "left in rock" hint, shown only while the beam is cutting). Under the place name, `instanceHtml` draws the panel for a run in progress (step 14): the authored objective sentence with **— done** once it is met, `<name> collapses in mm:ss` while a clock runs, the canister line (`<name> is locked` / `is open — fly to it and press R`), and the exit line — open, or the template's own refusal, never a rule name. Rift doors, the way out and the prize canister are **labelled at all times** by `drawMarkers` (class `i`, each with its distance, pinned to the edge of the screen when behind the pilot): a run is a place with nothing else in it to judge distance by, and losing the way out is losing the ship. Hints persist until the next sim tick so high-refresh screens do not flicker. The canvas hides the system pointer in flight because the HUD draws its own reticle; `setReticle()` hides the HUD **and** adds `body.no-reticle` together (title screen and docked), so the real pointer is always visible whenever the reticle is not. |
| `screens.js` | HTML for the intro and each outpost tab. Pure functions of state. `TABS` and `SCREENS` list the tabs. The Shop tab draws whatever `shopList(shopId)` returns from `data/shops.js` for the current station feature's `shop` — its rows, prices and "N left" — so a new row is a data edit. The Inventory tab shows the station's store above one ship's hold (arrows browse the ships; `viewedShip()`), each in a compact grid of clickable item tiles with m³. Click moves one item, Shift-click moves the whole stack, and right-click opens item actions: **Sell** (with its quantity box) and **Discard ×N** for the whole stack. A tile's label is the item's own kind (`itemUse` → **USE**, else **ORE** or **MOD**) and its sub-line is worded by category, so a consumable reads like one; there is no **Use** here — the owner put consumables in the flight card (`cargo.js`), which is where a rift can actually be opened. Selling opens a small in-game box beside the selected item to enter a quantity, defaulting to the full stack. Each hold uses a fixed 5-by-5 slot field with a three-row viewport; both grids scroll independently, even when mostly empty. |
| `menu.js` | The outpost panel: `ACTIONS` (one function per button, `data-a` name) and the click handler. Boot/slot/import/reset prepare the saved seed before applying it; safe-recovery notices survive alongside load/import success messages. Story mission offers are accepted through the same data mission runner, and only at the station that offers them. Contract-board actions act on **this station's** board (`acceptContract`/`rerollBoard` take the place), mission buttons arrive as mission ids, and `mission-ui-refresh` redraws the panel while it is open. Right-clicking an inventory tile opens the item menu: **Sell** (with its quantity box) and **Discard ×N** (no **Use** here: a consumable is used in flight, in `cargo.js`), which opens the shared two-step Discard popover (`discard.js`) — how many, then "Are you sure?" — before trashing from that tile's own place (station store or that ship's hold); a discard then retries pending mission hand-offs. |
| `cargo.js` | The flight inventory (press **I** in space): a modal card outside the docked panel, drawn by `screens.js` `cargoHtml()` in the same tiles as the station Inventory tab but **7 tiles across and 5 rows down** in a wider card, read-only — only the hold of the ship being flown, with no moves, no selling and no explanatory sub-line — but a right-click menu with **Use** and **Discard ×N**, the two things a pilot can do with cargo in space. **Use** appears only for an item with a `use` field and runs `sim/consumables.js` `useItem`: exactly one unit is spent, and only when the action worked; the returned sentence is shown as a notice, the card closes on success and is redrawn on a refusal. **Discard** opens the same two-step popover as the station (how many, then "Are you sure you want to discard …?"), and a mission item is refused. `canOpenCargo()` refuses while docked (the station panel has its own Inventory tab), dead, warping or with another overlay up; opening releases flight input but the world keeps running (audio included) and closing hands the controls back. A station, the title screen or death closes it. |
| `discard.js` | The Discard popover, shared by the station panel and the flight card: step one asks **how many** in the sell box's number field (defaulting to the whole stack), step two asks **"Are you sure you want to discard 3 Ferrite?"** with "It cannot be recovered." — nothing leaves the hold until that is confirmed. Enter commits the visible step, Esc closes the box, and `onDiscard(where, id, amount)` runs only after the second step. |
| `notice.js` | The docked panel's messages: routine confirmations say nothing (they only restate what the redrawn panel shows), and anything the pilot must read — a refusal, a save failure, a recovery warning — appears in a fixed `#panel-notice` element outside the panel — centred, and hanging just below the flight message line (`#msg`: the centred line that says "Empty weapon slot" on an empty weapon switch, or names the warp). `placeNotice()` measures that line on every notice so the two never touch, and works the same band out from the viewport height when the HUD is away — so no action can push the screen around. `isRoutineReply` lists the silent replies; `shownNotice()` is what is on screen. The "mission failed" alert stays in `missionlog.js` and was not touched. |
| `missionlog.js` | Step 13c mission presentation: the docked Mission log tab and the live dialogue panel. It renders data-defined speaker/portrait/text/choices, advances dialogue through `sim/missions.js`, saves after choices/lines, gates only authored station-contact dialogue with **Redock to continue talking** while undocked, refreshes after inventory changes so blocked hand-offs can continue, and leaves in-field dialogue actionable during flight unless a dialogue step explicitly asks to pause. Its status reads Active / Awaiting cargo / Ready to hand in / Complete, a recovery contract's tally reads **2 out of 3 crates recovered** rather than a bare "0 of 3", and its button is **Hand in cargo** when goods are owed (Abandon is always available when not ready). It lists every active mission at every station — progress follows the pilot — with only the hand-in bound to the mission's own station (elsewhere the button names it and is disabled, Abandon still works); an empty station just says "No active missions here." with nothing about work elsewhere, and the story offers are only the ones this station gives out; after every mission event it emits `mission-ui-refresh` so the open docked panel redraws — closing a final dialogue therefore updates the card at once. It also shows the red notice (`failureNoticeHtml`, "Mission failed" or "Contract failed" by the mission's kind) when `mission-failed` fires for any reason except the pilot abandoning. |
| `picker.js` | Which Outfitting bay picker is open: `toggleModulePicker`, `togglePaintPicker`. Pure, one at a time, tested in `tests/picker.test.mjs`. |
| `outfitting.js` | The Outfitting tab's 3D window: mounts the ship canvas into `#shipview` after every panel redraw, wires drag/zoom, draws one frame per game frame. |
| `pause.js` | The pause overlay: PAUSED title, resume hint, **Resume** first, sound on/off switch, **Exit to main menu** last (markup in `overlays.js`). Exiting saves the current resume point, returns to the title menu and leaves Campaign disabled while Open World uses the existing intro action; `core/audio.js` fades every loop to silence for it. P closes an open starmap first, then pauses; Esc only closes the chart. |
| `overlays.js` | The rules for the two full-screen overlays and the pause card's markup. `canPause()` and `canOpenStarmap()`: both are available **anywhere in the open world, docked included** — only the title screen, the pause overlay itself, a dead pilot or a warp in progress refuses. `pauseOverlayHtml()` keeps Resume at the top and Exit to main menu at the bottom. |
| `starmap.js` | The M chart: visible system web, gate lines, current/selected markers (visited knowledge is retained without a separate light-blue style), inspect dropdown and zoom/pan/labels. Zooming into a selected system dot opens a derived pocket map with a short zoom transition: pockets orbit a visual-only star/black hole with a permanent two-line name/type label; native hover tooltips are gone from pockets/core, while right-click popups remain. Core radii are map units so the graphic scales with system zoom; pocket dots/labels stay screen-sized. `pocketLabelLayout` keeps pocket names off nearby dots and apart from each other, connecting a nudged label back to its dot. Galaxy pan is bounded to 0.5–1 screen pixels per pointer pixel, increasing gently when zoomed out. Free-warp systems omit ordinary internal lines; route-only systems draw them. When a route is active, consecutive pocket hops in the viewed system get solid orange overlays with directional arrows, while incoming/outgoing cross-system gate exits stay orange dashed; galaxy route links are solid orange with the same arrows. Gate exit stubs point toward neighbouring systems, gate pockets and their labels can be double-clicked to open the peer map; their first click is delayed just enough for the browser's native double-click event to reach the original SVG node. Neighbouring-system labels are clickable travel targets quoting the reciprocal gate pocket. Closing/reopening restores the session-only view and framing; on cross-system travel a remembered pocket view follows the local pilot to the new system (resetting pocket framing), while the galaxy view stays open at galaxy level. Right-click a galaxy system to set a saved destination or, when at its direct gate, warp to it. Pocket and gate-peer popups open just to the pointer's right with **Set destination** first, then offer **Warp to** only for a legal hop; map charts render no bottom status/refusal notices. Straight connections meet their endpoint dots; chart-only node layout avoids unrelated dots; a highlighted path and route stops appear beneath the pocket rows (long names wrap), with pagination only when the available space cannot fit them; J in flight advances one checked warp hop. The right panel is a compact system/current-pocket/pocket-row overview. Right-clicking a pocket dot or gate-neighbour label emits `action { name: "travel", to }` only after the existing quote/recheck; left-clicking a pocket-map pocket does nothing; main calls `startWarp`, which rechecks it. The chart never stops the clock: it releases flight input and blocks the dock/lock/weapon/jump hotkeys, but `isSimulationPaused()` counts only the pause card and the title screen, so the world and its audio keep running behind it in every mode. |
| `route-display.js` | Shared route presentation for the HUD and starmap: remaining system names with start, blue-intermediate and amber destination markers, respecting discovery visibility. Exact pocket destinations use `Route to Pocket`; the final system row still adds the pocket in a small parenthetical, while system destinations remain system-only. |
| `warpflash.js` | The warp vignette and white-out. Two gradients, updated from `state.warp` each frame. |

Rules:
- Buttons carry `data-a` (action name) and optional `data-b` (argument). The Shop's Buy button is
  `data-a="wb" data-b="shopId:itemId"`. The panel re-renders and autosaves after each click.
- Styling lives in `src/styles.css` (labelled sections; the pause menu has its own).
- New tab: `docs/HOW_TO_ADD.md` recipe 7.
- Inventory buttons carry `data-a="mv"` with `data-b="kind:id:dir:n"` (kind `c` goods or `m` module — only what the tile shows, since one `moveItem` moves either — dir `s` station to the ship shown or `t` back, n a count or `all`). The tiles come from `itemsAt(place)` in `sim/inventory.js`, which lists goods in catalogue order and then spare modules in the order they arrived.
- A bay opens a picker: `data-a="slot"` (module, `data-b` is `group:bay`) or `data-a="paint"` (paint, `data-b` is the paint id). The rule lives in `picker.js`.

`chart-lines.js` computes a cached, derived visual layout that nudges unrelated dots away from straight gate connections; it does not alter simulation positions. In crowded cases the chart masks only obstructing unrelated dots, never both endpoints globally. Highlighted routes reuse the same straight geometry.
