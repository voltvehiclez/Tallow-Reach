# src/state: runtime state and saves

| File | What it does |
|---|---|
| `state.js` | Runtime `state`: `profile` (local pilot's portable character), `worldState` (hosted world's persistent `stationStores`, legacy home `store` alias, `base` and `board`), `players`, `localPlayerIndex`, per-place transient containers (`places`, `placeWorld(id)`), local aliases `place`/`world`/`warp`, and `time`. Each player owns `profile`, controls, `place`, `warp`, flight/lock/cooldowns, power, drive, shield, hull capacity and equipped weapons. `state.player`, `state.controls`, `state.flight`, `state.power`, `state.drive`, `state.shield`, `state.hull`, `state.guns`, `state.beams` and `state.missiles` alias the local player (`ui.board` aliases `worldState.board`). `profileOf(player)`, `currentSave()` and `applySave(save)` connect runtime and save halves. `currentSave()` captures first: `captureResume()` records where the local pilot is — inside a temporary run that means inside it — and `captureInstances()` writes every live run into `world.instances` (slice 14b), so a save made mid-rift is a save of the run. Session-only `galaxy` holds the resolved web, `galaxyRecovery` a pending safe-recovery notice, `multiplayer` the future host flag, `ui.starmap` the open chart view, and `ui.starmapMemory` the last closed chart presentation, and `ui.destination` the chosen system or exact pocket (mirrored to saved `world.destination`; chart framing alone is session-only). `captureResume()` records the local pilot's spot into `worldState.resume` (null while docked); `currentSave()` calls it, so autosaves, slots and export codes all record where the pilot is. |
| `profile.js` | The saved game (`SAVE_VERSION = 20`): `newProfile()`, `newWorld()`, `newGalaxyRecord()`, `newSave()`, `sanitizeProfile()`, `sanitizeWorld()`, `sanitizeSave()`, `addShipRecords(profile, id)` (a hull that joins the fleet: its own empty hold, a full hull fraction and the stock fit) and `ensureShipRecords(profile, id)` (fills in only what a hull is missing), plus co-op helpers `portableProfile(save)` and `mergeProfile(save, profile)`. `world.stationStores` is keyed by the stable `${placeId}:${featureId}` station identity; the enumerable `world.store` property aliases the home station for old callers and saves. A legacy v18 world with only `world.store` is assigned to its saved station when possible. `profile.missions` and `profile.flags` are portable mission state, and `profile.mission` is a non-enumerable compatibility view. `world.galaxy` is only `{ seed, knowledge }`; generated geography is never saved. `world.placeMemory` keeps positive simulation-second cooldowns for mined rock slots and cleared encounter features. `world.instances` (v20) keeps the temporary runs a pilot is inside — one entry per run with its template, seed, tier, remaining lifetime, objective, canister stock and entry spot — and `world.place` may name one; `cleanInstanceRuns` drops any run whose id `instanceIdFor` would not produce, and a place that is then nowhere sends the pilot home. Everything that is saved goes through here. |
| `controls.js` | The control record: one plain object per pilot with what that pilot is asking the ship to do this frame (steer, roll, throttle, fire, boost...). `core/input.js` fills the local player's copy; `sim/` only reads it; a network guest's copy will have the same shape. |
| `destination.js` | Updates the local route target and autosaves it immediately; the path is always recomputed. |
| `storage.js` | Autosave (`tr1`), three save slots (`tr_s1`..`tr_s3`) and text save codes (`TR1:`), storing `{ v: 19, profile, world }` while transparently migrating v18 and older saves plus legacy worlds without `stationStores`. `profile.missions` and `profile.flags` are portable mission state. `loadAutosave`/`decodeSave` accept a preparation callback; boot, slot load and import pass `prepareGalaxySave` so the saved seed is installed before pocket ids are validated. Storage keys and prefix must not change. |

Rules:
- Changing saved data normally means: default in `newProfile` or `newWorld`, validation in `sanitizeProfile` or `sanitizeWorld` (invoked by `sanitizeSave`), bump `SAVE_VERSION`, a "Version history" line, and a test. The station-local `stationStores` extension was introduced as an optional v18 field; current v19 saves also migrate legacy `world.store`, and mission progress migrates the former singular `profile.mission`. See `docs/ARCHITECTURE.md`.
- World-dependent validation runs after `sim/galaxy-session.js` installs the candidate seed. A removed/unknown pocket recovers to the home station with `resume: null`, preserving the whole profile; a failed prepare restores the previous live catalog.
- `sanitizeWorld` walks `BASE_MODULES` (`data/station.js`) automatically; `sanitizeProfile` validates `msl` against fitted launcher capacity.
- Groups added in a later version (thrusters in v5, shields in v6, cannons in v7, hull in v10) are retrofitted by `cleanLoadouts` for older saves; a save of the current version keeps a bay the player emptied.
- `profile.holds[shipId]` is each ship's own hold (travels with the pilot) and `world.stationStores[stationKey]` is the hosted station-local storage: each value is one `{ itemId: count }` stock. `world.store` (`state.worldState.store`) is an enumerable compatibility alias for the home station. Save v12 unified stocks; save v13 split pilot holds from station storage; v18 added station-local records and v19 added `missions`/`flags` to the portable profile. No empty counts are kept.
- A ship **is** its fleet records: `holds[id]`, `hp[id]` and `loadout[id]`. A hull id alone is not a ship — with no
  `loadout[id]` it has no bays to fit and nothing to fly with (no Hull HP, thrusters, shields or guns). Add a hull with
  `addShipRecords`, never with a bare `ships.push`, and repair an incomplete one with `ensureShipRecords`.
- `profile.loadout` holds the modules fitted to each hull: group id -> one entry per bay (`null` = empty). Only `sim/fitting.js` writes it. `cleanLoadouts` drops unknown ids and bays past the hull's layout, and gives a hull with no saved loadout the stock fit. `cleanStock` keeps a place to known items, whole counts above zero.
