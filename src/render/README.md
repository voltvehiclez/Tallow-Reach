# src/render: what you see in 3D

Visual only. Reads `state` and the sim, never changes game rules. Visual random choices use
`cosmeticRandom` so render frame rate does not consume seeded gameplay rolls.

| File | What it does |
|---|---|
| `scene.js` | three.js renderer, lights, stars, and per-place scenery built from `PLACE_DEFS` features (station, planet). Each place gets its own group: `placeGroup(id)`, `showPlace(id)` to show one place and hide the rest, `updateScenery(dt)` for visual spin. Step 14 added **skies**: `SKIES` is a registry of builders keyed by a place's own `sky.kind` (`placeAt(id).sky`, vocabulary in `data/instances.js` `SKY_KINDS`), each returning `{ object, spins, dispose }` like a scenery model; `SKIES.shattered` is the collapsing shell of dark panels, glowing fractures and drifting shards a rift is seen under. A place with a sky hides the ordinary starfield (`showPlace`) and carries its sky with the camera (`updateScenery`). `forgetPlace(id)` removes a place's group for good and runs its sky's `dispose` — used for a destroyed instance, which never comes back (`main.js` on `instance-closed`, and on `instances-forgotten` after a load). Scenery jitter uses `cosmeticRandom()` only. |
| `models.js` | Ship and asteroid meshes. `mkShip`, `buildPlayerShip(id)`, `rockShapeAt(k)` (`ROCK_SHAPE_COUNT` shapes; a rock's record says which: `shape`). |
| `views.js` | **Every mesh in the world except the scenery.** One mesh per entity, kept in step with the sim's plain data: `installEnemyViews()` at boot, `updateEnemyViews()` once a frame. Since step 7a a hostile is data (`enemy-spawned` / `enemy-removed`); since 7b so is everything else — bullets, missiles, crates, explosion sparks, rocks, and the player's own ship (built from `profile.ship`, hidden while docked). `PlayerShipView` owns the local player hull, selected by `localPlayer()`, and exposes the same named mount data the sim uses. It also draws the mining beam from `state.flight.beamStart` / `beamEnd`. `registerEntityView(kind, { list, build, update, remove })` registers a kind; one live-view map holds all kinds, with separate enemy/entity ID namespaces. `entityViewCount()` and `enemyViewCount()` count the respective views. Step 14 added three more kinds: `rift` (a door hanging in a pocket) and `gate` (the way out inside a run) are both **the same shimmering anomaly** — a dark spherical core with a bright eye, an additive aura and a wider flare, breathing from `performance.now()` with a per-entity phase, plus sealed shells while locked — drawn by one shared `buildAnomaly`/`updateAnomaly` pair, so a way out always looks like the way in; `cache` is the prize **canister** (a drum, two caps, two bands and a lamp that is red while sealed and green once open). Each is built from its record's `pos`, `quat`, `spin` and radius `r` and shares one geometry and material per kind. Builds a mesh on `entity-spawned`, removes it on `entity-removed`, and sweeps the lists every frame so nothing is ever left behind. |
| `menuview.js` | The title screen's own scene: the home station turning with its planet behind it, on the camera path in `MENU_CAMERA`/`menuPose` (`data/camera.js`). Independent of the game scene, so the menu never shows the last game view. `updateMenuView(dt)`, `menuView()`, `resizeMenuView()`; driven by `main.js` only. |
| `camera.js` | Docked orbit, chase camera, free orbit (Alt), screen shake, the FOV/roll kick during a warp. The chase distance behind the ship is the `CAMERA` table in `data/camera.js` and nothing else: the camera rides along with the ship's movement and only eases the offset. |
| `warpfx.js` | The warp streaks: additive lines hanging off the camera, driven by `state.warp.fx`. Hidden when no warp is running. |
| `shipviewer.js` | The Outfitting ship view: its own renderer, scene, lights and turntable. `setShip(id)`, `dragShip`, `zoomShip`, `resizeShipViewer`, `renderShip(dt)`. Owned by `ui/outfitting.js`. |

Rules:
- three.js is bundled by `npm run build`. Do not add other libraries.
- A new ship needs no change here unless it has a visible add-on (`buildPlayerShip`).
- **A new entity kind is drawn here, never in `sim/`.** Give it a `kind` in its record and register its list, mesh builder, per-frame updater and
  cleanup in `views.js` (see recipe 19 in `docs/HOW_TO_ADD.md`); `tests/layers.test.mjs` fails if a `sim/` file's code names a mesh, a material
  or the scene, and `tests/views.test.mjs` counts the meshes.

The current player hull and beam views follow the **local** player only; see the still-local-only table in `docs/TARGET_ARCHITECTURE.md`.
