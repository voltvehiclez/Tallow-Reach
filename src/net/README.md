# src/net: multiplayer (refactor step 16)

Two friends play co-op: one **hosts** their open world and the other **joins** it through a
WebRTC link. The host's browser runs the one true simulation; the guest sends what it is asking
its ship to do and draws what the host sends back.

**This folder is the only place a connection may live.** Nothing in `src/sim/` imports it (the
layer test does not need to list it: `sim/` imports it never), and `ui/` and `render/` talk to it
through `util/events.js` and through `state.players`, which already holds every pilot. Slice 3 adds
the connection: `transport.js` (the one thin wrapper around the connection library), `session.js`
(one session, and what a screen draws from it), `protocol.js` (the wire's messages), `paste.js` (the
broker-free fallback), `join-link.js` (the one link a guest needs), `settings.js` (the username) and
`boot.js` (a `?join=` link in the address bar). Slices 1 and 2 are the rules and their save fields; slice 8a adds `ships.js`, the picture of every
pilot the host sends 24 times a second (the guest draws it and simulates nothing).

**Step 17 (planned 2026-11-22): dedicated servers.** The server side of the connection will live here too — a
headless build of the same project (no `ui/`, `render/` or `core/`) hosting one world for 50+ players via port
forwarding, with the wrapper still the only file that names a connection library. The plan is step 17 of
`docs/REFACTOR_PLAN.md`.

| File | What it does |
|---|---|
| `custody.js` | **The pilot's suitcase.** `checkOut(save)` packs the open-world pilot into a `bundle` (the `TRAVEL_FIELDS` half of the profile plus the station lockers, each stack carrying its `origin` station) and writes the `away` marker; `checkIn(save, bundle)` puts it back into a *new* save, clearing `away`, merging the home half (missions, flags, stats) from the home save untouched; `relocate(bundle, world, options)` sends anything whose station a world lacks to Meridian and puts it back the moment that station exists again, never refusing or deleting, and flags an over-full station; `compare(a, b)` orders two copies by `(epoch, rev)`. It also holds the small facts a host needs: `hashToken`/`tokenCheck` (the host stores a hash, never the secret), `handshake` (version, world and token, each with a sentence for the refusal), `guestRecord`, `summary(bundle)` ("600 cr · 1 ship · 0 m³"), `uniqueName` (the host's name wins, joiners wear `*`, `**`), `mergeLockers`, `hostProfile` and `totals` (what left vs what arrived, for tests). Plain data in, plain data out: no DOM, no three.js, no save it was handed is mutated. |
| `multiplayer.js` | **The save fields, changed in one place.** `worldIdFor` mints a world's id once and keeps it; `adoptHostWorld` sets `save.away` and writes the suitcase under `away:<worldId>`; `syncAway` stores the host's newer copy; `leaveHostWorld` clears the marker and forgets the per-world key; `guestOf`/`putGuest`/`dropGuest`/`guestList`/`seenGuest`/`guestIsHere`/`guestCount`/`canTakeGuest` are the host's side of `world.guests`; `isAway`/`awayLine`/`suitcaseKey` answer "is this pilot home?" for a screen. Every function returns a new save and none mutates its argument. Nothing here trusts a token: a guest record is built by `custody.guestRecord`, which strips the guest's secret. |
| `station-inventory.js` | **Room at a station, defined once.** `inventoryOf(world)` reads `world.stationStores` (or a plain station map) into clean stocks — keeping an id this build does not know, because custody must carry it; `stockVolume`, `stationCapacity(world)` (the shared per-level figure in `data/station.js`), `stationRoom`, `stationSpaceFor` (free m³ and the stack rule); `guardOverfull(world)` flags any station holding more than it can as `world.storageOverfull[key]`, which only refuses *new* deposits and never deletes a unit. Slice 6's trade asks the same questions. |
| `transport.js` | **The one wrapper around the connection library.** `createChannel({role, worldId, onState, onData, onPeer})` returns `{join, send, broadcast, leave, peers, state, room}`; `roomNameFor(worldId)` is `tallowreach.p2p:<worldId>`; states are `idle · finding · connected · lost · closed`, and `stateLine()` turns one into a sentence. The library (`trystero`, pinned `0.27.0`, MIT) is imported lazily here and **nowhere else** (`setLibraryLoader` swaps it for an in-memory relay in tests); every failure — no relay, no browser support, a closed room — becomes `lost` with a sentence, and nothing throws. `RELAYS.relayUrls` in `data/multiplayer.js` **names the five signalling relays** — left empty the library shuffles thirty public ones by app id and this game drew three dead servers, which is why playtest 5 saw two browsers sit in rooms of one. `checkRelays()` opens a WebSocket to each and returns `{ total, open }` (in `diagnostics()`, shown as *Relays reachable*); `setRelayProbe(null)` keeps tests off the network. **`Relays connected: N`** is the library's own view (`getRelaySockets()`): a relay that accepts a socket and then refuses these events is retired by the library, so a high `reachable` beside a low `connected` means the relays are alive but will not carry this protocol. Pasted offer/answer codes (`paste.js`) stay as the fallback for a network that will not reach a relay. |
| `session.js` | **One session, and what a screen draws.** `hostWorld({save, name})` gives the world an id the first time and returns the link; `joinWorld({link})` joins one; `codesOffer`/`codesAccept`/`codesFinish` drive the paste fallback. It answers the handshake with `custody.handshake` (and records the guest with `putGuest`, so the save keeps a hash and never the secret), keeps the guest list and the recent chat, and emits `mp-state` on the bus. **It moves no pilot**: the suitcase is slice 4, so a bug here cannot cost anybody a ship. `setSaveKit` and `setChannelFactory` are the two seams a test uses to drive two sessions against each other with no browser. **Two save shapes live here:** `saveKit.read()` hands over a **MODE** save (`{profile, world, away}` — one pilot), while a *root* save is the dual-mode envelope (`{v, mode, open, campaign}`). `bringPilotHomeAtMenu` accepts both (`isModeSave`) and writes back the shape it was given; guessing one for the other refuses a healthy save (playtest 15, L38). `joinWorld` refuses a join only to a **different** world than the one an away pilot is already visiting, so a rejoin can do what it says. **Slice 5:** `markHostLost` states a lost host (a departing peer, or silence — `checkHostAlive`) once, as `mp-host-left`, and touches no save; `ui/` stops the session and puts the main menu up with "Lost connection to host". `syncGuests` is the host's every-`NET.snapshotSec` check that writes a visiting pilot's live profile back (before it, `writeBack` had no caller). `onCarry` lets `compare` and a `left` record decide whose copy wins, never arrival order — and a rejoin keeps what the server has, so `sendCarryMessage` puts the guest's secret back from `away.token` (the copy it keeps is the host's, which has none). `bye` on stop and on `pagehide` ends a visit at once; a hello from another live peer for the same `guestId` takes the pilot over (`refuse` reason `replaced`, older window stops **quietly**) — `guestId` comes from this browser's `pilotToken`, not from the link's secret, so different browsers on one link are different guests (playtest 22). |
| `protocol.js` | **The wire, small and validated.** Eleven kinds — `hello`, `welcome`, `refuse`, `chat`, `presence`, `ping`, `pong`, `carry` and `suitcase` (the pilot), `bye` (slice 5: "I am leaving", so the host takes a final copy and lets the pilot go at once) and `ships` (slice 8a: where every pilot is) — each cleaned to its own fields and its own length (`chatLineMax`, `nameMax`, 32-item lists, `suitcaseMaxBytes`, `LIMITS.ships` pilots per ship packet) on the way out *and* in, so a peer cannot flood the other side. `readMessage` is the only reader and drops anything this build does not know (a newer peer's message, junk). A bundle is shape-checked and size-capped but its content ids are never stripped (L16). `LIMITS` is exported because a sender batches by it (`session.js` sends one `ships` message per 24 pilots rather than dropping the rest). |
| `turn.js` | **Which relay (TURN) servers this browser may use, and whether they answer.** `ownRelay(settings)` reads the player's own server from `tr_mp.relay` (three strings or nothing — a server with no login answers `401` and looks like a network fault); `turnServers()` puts theirs first and the game's built-in one behind it (`builtinRelays()`, `builtinRelayName()`, from `ICE.turn` — ExpressTURN's free tier, two doors, UDP 3478 and TCP 3478); `iceServers()` is the whole ICE config (STUN + both); `checkTurnServers()` asks each server for a relayed address with `iceTransportPolicy: "relay"` and counts the ones that answer — the only honest answer to "why does 4G fail: them or me"; `turnSummary()` says it in one sentence. |
| `paste.js` | **The broker-free fallback.** `createPasteLink` makes a full, non-trickling `RTCPeerConnection` offer (one code, not a stream of candidates), takes an answer back, and hands on the same `send`/`state`/`leave` vocabulary as a channel. `pack`/`unpack` wrap a code as `TRJOIN:` + base64; whitespace from a chat app is ignored, anything else is refused. It uses the browser's own WebRTC and no library, so it works when the library or its relays do not — and it always offers `ICE.turn` beside its STUN, because a player only reaches for codes after the easy route failed. |
| `join-link.js` | **One link, as the owner designed it:** `?join=<worldId>#<token>`. The secret rides after the `#`, which a browser never sends to a server and never leaks in a referrer. `readJoinLink` pulls a link out of a whole pasted sentence, strips chat quotes, and refuses a half link with a sentence that names the missing part. `linkFromLocation`/`forgetLink` are how `?join=` is taken once at boot. |
| `ships.js` | **The picture of every pilot** (slice 8a). `shipEntry(P, {id, name})` turns one live player record into exactly the fields `SHIP_FIELDS` names (`data/multiplayer.js`) — id, name, ship, place, position, rotation, velocity, throttle, docked, dead, hull fraction, shield fraction (playtest 23) — as plain arrays and numbers; `shipEntries(players, {localIndex, localName})` does every record, the host's own first under `HOST_PILOT_ID`; `hullFraction(P)`/`shieldFraction(P)` are re-exported from `sim/pilot-stats.js` (one place, so the host's own screen and the wire agree); `hullFor(entry)`. It reads records it is handed and writes nothing: `session.js` asks for the picture on the bus (`mp-ships-request`), `main.js` answers with this file. That keeps the wire one-way (host → guest) and keeps `net/` out of the simulation. Tests: `tests/multiplayer-slice8a.test.mjs`. |
| `settings.js` | **The username, the two switches and this browser's pilot token** (`localStorage` `tr_mp` → `{name, enabled, autoJoin, pilotToken}`). A name is text or nothing — a number in storage is refused, not turned into `"42"` — capped at `NET.nameMax`, whitespace collapsed. `pilotToken` is this browser's guest identity (playtest 22, L47): made once with `makeToken(NET.tokenBytes)`, cleanToken-checked, never shown and never in a save; `net/session.js` exposes it as `guestToken()`/`pilotToken()` and both doors in send it, so **two friends on one join link are two pilots**. Storage that refuses writes (a private window) still gives a working session with no memory. |
| `boot.js` | **A `?join=` link in the address bar.** It asks first (a browser `confirm`, so a stray link costs one Cancel), takes the link out of the bar once used, refuses with words while a campaign act is loaded, and with no username yet it keeps the link and says where to set one. It has **no screen**: it says what happened with `mp-notice` on the bus, because `net/` may not import `ui/`. |
| `world-places.js` | **Where a station is in somebody else's world.** Generated pocket ids are **not unique across galaxy seeds** (`sys-002-hub` is a different pocket in a different galaxy), so a station key is always read with the world it belongs to: `stationsOf(galaxy)` indexes a resolved galaxy; `stationsOfWorld(world)` indexes a save's own world from `world.galaxy.seed` plus its saved wormhole pockets; `stationIn(index, key)` is the one question custody asks; `stationKeys`, `sameWorld`, `authoredStations`. Building an index never touches the live catalog (`data/places.js`), so inspecting another world cannot move the ground under the running game. |

**Rules**

- Saves stay backward-compatible: `save.away`, `world.worldId` and `world.guests` are **save v29**
  (slice 2, built), and every older save loads with `away: null`, `worldId: null` and `guests: {}`.
  The marker lives beside `profile`/`world`, never inside a profile.
- Only `data/multiplayer.js` says what travels. Adding a saved profile field makes
  `tests/multiplayer-custody.test.mjs` fail until it is listed as travelling or staying home.
- **Items are moved, never copied.** A stack that leaves is the only copy; `totals()` proves it.
- A host's copy of a guest is `world.guests[guestId]` (slice 2): `{ name, tokenHash, epoch, rev, bundle, lastSeen }`.
  Deleting that entry is always safe, because the guest's suitcase has a copy.
- **Nothing in this folder may import `core/`, `ui/` or `render/`** — it is below all three, like `sim/`.
- **`transport.js` is the only file that names the library.** The layers test checks it.
- **A session must survive its wire failing.** Every path out of `transport.js` and `paste.js` ends
  in a state and a printable sentence; nothing in this folder throws at the player.
- **A hosted world never pauses** (`sim/step.js` reads `state.multiplayer`), because the guests are
  still flying in it. That is why the pause card is a settings panel while multiplayer is on.
- **The guest's hello is per peer and repeated until a welcome arrives** (`sayHello`,
  `greetEveryone`, `startHelloRetry`, `NET.helloRetrySec` / `helloWaitSec`). "Sent" is not "heard": a
  data channel can open seconds after the room reports the peer, and a message into an unopened
  channel vanishes silently. The reply is the only latch, and after `helloWaitSec` the guest is told
  which of the two failures it is having.
- **A relay is the second path** (`ICE.turn`, `useTurn`, `channel.restart({ useTurn })`,
  `session.reconnect`, `escalateToRelay`). The signalling relay introducing two browsers is not a
  data path; two machines on a home network often have none (no hairpin NAT, mDNS dropped), and two
  tabs on one machine hide it. Both ends escalate after `NET.helloWaitSec`, because a relayed path
  needs a relay candidate from each side. `channel.diagnostics()` is what the screen reports.
- **The newest copy wins, and the guest's own suitcase is what comes home.** The host writes a
  visitor's live profile back on a real change (`syncGuests`), a `rev` raise is never more than one
  per `NET.revStepMs`, and the message follows `NET.snapshotSec` later. `compare` (slice 1) orders
  two copies on the wire, plus one fact it cannot express: a record marked `left` is holding a
  suitcase, not an identity, so a pilot that has been home since hands over its own save. **The
  player is asked nothing**: bringing a pilot home installs the copy that world holds, however
  little looks different (owner, `2026-11-24c` — `newerCopyAway`/`isNewerCopy` are deleted).
- **A pilot lives in one window.** A hello for the same `guestId` from a different live peer is a
  takeover: the older window is told in words and stops **quietly** — a `bye` from it would make the
  host mark the pilot gone and take its ship out of the world.
- **`snapshot().hostName`** is the host's name, learnt from `welcome`; the guest's player list cannot
  be built without it (`guests` only ever holds guests).
- **A duplicate name gets a star** (owner's rule): `uniqueName(wanted, taken)` gives the joining guest
  the first free variant (`Acey`, `Acey*`, `Acey**`), counted against the host and every guest but its
  own row, and the host sends it back as `welcome.youName`. Names are labels; the link's secret is the
  identity.
- **A paste code names its world** (`paste.js`, `CODE_VERSION` 2). `session.codesAcceptFrom(offer)`
  builds the guest session from the code, so the fallback does not need a working link first.
- **Chat is an `<input>`.** `core/input.js` already ignores keys aimed at a text field, so typing a
  message cannot fly the ship; the box also stops its own keys reaching the game's bindings.
